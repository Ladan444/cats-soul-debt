# Долг Кошачьей Души — HD-2D игра на Godot

Этот файл подгружается в каждое сообщение — здесь только карта и правила. Подробности по подсистемам —
`Литература/TECH_NOTES.md`: **перед работой над подсистемой читать её раздел** (список: `grep -n "^## " Литература/TECH_NOTES.md`)
и после изменений обновлять его там, а не здесь.

## Правила работы
- Лор: `Литература/CANON.md` — единый источник правды (при противоречиях верен он). Стиль, палитры, свет — `PROJECT_BIBLE.md`.
  Сюжетные решения согласовывать с автором, итог вносить в CANON.md.
- Перед новой задачей — уточняющие вопросы автору. «Готово» — только после одобрения или показанного доказательства (скриншот, тест).
- `PROGRESS.md` — журнал и планы по эпикам: обновлять после каждого шага (статус `[~ ждёт одобрения]` до одобрения).
- Трекер автора — веб-таблица https://claude.ai/artifact/JFTsAfycAqDKtdyfjUjwL5 (инструмент `ArtifactData`, коллекции
  `epics` {name, order, percent, chat, summary} и `tasks` {code, epic, title, status: done|review|progress|todo, priority, updated, note}).
  После шага — обновить/добавить строку задачи своего эпика (`update` с `if_version`) и процент эпика. «Готово» ставит только автор.
- Чаты marketing, team, business пишут только в `Проект/` и трекер; ничего не публикуют и не отправляют от имени автора — только готовят тексты.
- Работа разбита на чаты по эпикам: world, characters, combat, audio, ui, story. Чат правит только файлы своего эпика;
  общие (project.godot, autoload-скрипты, CLAUDE.md) — согласовать с автором; Godot-импорт и Blender — по одному процессу за раз.
- Новый .md в `Литература/` или `Проект/` — после создания запустить `python Tools/obsidian_hubs.py` (оглавления для графа Obsidian, иначе файл висит «сиротой»).
- После законченного шага — бэкап: `powershell -File Tools/backup.ps1 "что сделано"` (robocopy-зеркало + git-коммит в `C:\Users\Ladan444\The cat's soul debt`).
- Все персонажи — антропоморфные звери. Комментарии и имена узлов можно по-русски, идентификаторы кода — по-английски.

## Экономия контекста
- Godot запускать через `powershell -File Tools/godot_run.ps1 <режим> [путь]` — на экран только итоги и ошибки
  (режимы `import`, `script`, `htest`, `test` в окне 1280×720, `export`; цепочка: `"import,script:<путь>,test:<путь>"`).
- Код в Blender (MCP): `exec(open(r"<путь>", encoding="utf-8").read(), ns)` внутри `contextlib.redirect_stdout(io.StringIO())`,
  возвращать короткий dict, а не логи. Сборка мира ~35 с, рендеры — отдельным вызовом.
- Скриншоты и рендеры склеивать в один лист: `python Tools/contact_sheet.py out.png a.png b.png ... [--crop x0,y0,x1,y1]`.
- Большие файлы читать кусками (offset/limit) или через grep; не перечитывать файл после Edit.
- Субагенты — для исследований, аудитов и черновиков текстов (только чтение или черновики в scratchpad). В канон, генераторы,
  сцены и `project.godot` пишет только основная сессия. Blender и импорт Godot — по одному процессу за раз.

## Движок и инструменты
- Godot 4.7.2, GDScript, Forward+. Проект `Game/CatsSoulDebt/`; консольный Godot `Game/Godot_v4.7.2-stable_win64_console.exe`.
- Python 3.14 + Pillow: `%LOCALAPPDATA%\Programs\Python\Python314\python.exe`; в PowerShell нужен `PYTHONIOENCODING=utf-8`.
  `.ps1` с кириллицей сохранять в UTF-8 с BOM.
- Blender 5.2 через MCP (`mcp__Blender__*`), русский интерфейс — узлы искать по типу. Оси: Blender (x, y, z) → Godot (x, z, −y).
- Временные тесты и скрипты — в scratchpad, не в проекте; тесты проекта — `Tools/godot/tests/`.

## Главные соглашения
- 2.5D: 3D-мир с пиксельными текстурами (nearest, 40 px/м), персонажи — `Sprite3D` billboard Y, shaded, alpha_cut, nearest.
  Рост персонажа ~48 px, чиби (голова ~35–40 % роста); 3 вида (вниз, вверх, вбок), влево — отражение.
- Камера «диорамы»: фиксированный наклон, FOV ~30, DOF. Атмосфера — `WorldEnvironment` по палитрам PROJECT_BIBLE.
- Управление: клавиатура, мышь и геймпад одновременно — у каждого действия InputMap привязки для клавиатуры и геймпада.
- Сцены уровней собирают генераторы (`Tools/godot/build_*.gd`) — ручные правки сцен теряются при пересборке.
