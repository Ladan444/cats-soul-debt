## Инструменты
- Временный арт из генераций arena.ai (2026-11-05): `python Tools/agent_strips.py [имя ...]` — листы агента (`Арт/Генерации/agent`, `agent_v2`) → полосы кадров в `Арт/Генерации/sprites_final` (фон заливкой от краёв, голова жителей к чиби); `python Tools/build_art_sheets.py` — полосы → игровые листы всех, кроме Рэя и чучела. **`Tools/rebuild_all.ps1` и `build_combat_sheets.py` запуском из консоли перезапишут эти листы старым артом** — не запускать.
- Черновики текстов пачками через Ollama: `python Tools/local_llm.py "задание" [--file задания.txt] [--context Литература/CANON.md] [--n 3] [--out файл.md]` (модель по умолчанию `gemma4:31b-cloud` — считается в облаке ollama.com; `--list` — модели). Только черновики (описания, слухи, варианты реплик, пересказы); результат сверять с каноном, в код и канон — через чат эпика.
- Python 3.14.8 + Pillow: `%LOCALAPPDATA%\Programs\Python\Python314\python.exe` (в PATH пользователя; в уже открытых терминалах — после перезапуска). Установлен из NuGet-пакета: MSI-установщик на этой системе не работает.
- Git: `C:\Program Files\Git\cmd\git.exe` (в PATH старых терминалов может не быть). Репозиторий автора — `C:\Users\Ladan444\The cat's soul debt` (внутри зеркало папки проекта, `.gitignore`: `.godot`, `Builds`, редактор Godot, скриншоты, `*.blend1`). Работаем в папке на рабочем столе; после каждого законченного шага — `powershell -File Tools/backup.ps1 "что сделано"` (зеркалирует robocopy и коммитит).
- Обработка ИИ-арта: `python Tools/sprite_pipeline.py "Арт/Генерации/<файл>" --name <имя> --palette <ключ>`; палитры в `Tools/palettes.json` (из SPRITE_SPECS). Результат — `Арт/Обработано/`, в игру копировать в `Game/CatsSoulDebt/assets/sprites/<персонаж>/`. Нужен `PYTHONIOENCODING=utf-8` в PowerShell.
- Пересборка всех спрайтов из генераций и копирование в игру: `powershell -File Tools/rebuild_all.ps1` (новые генерации вписывать в список `$jobs`; файл сохранять в UTF-8 с BOM — иначе PowerShell 5.1 ломает кириллицу в путях).
- Уменьшение — «по большинству» (каждый пиксель исходника сначала в палитру, итоговый пиксель = самый частый цвет блока); `accents` в palettes.json — мелкие важные цвета (глаза, шрамы), которые побеждают при доле ≥ 20 %. Тёмные цвета палитры подбирать по температуре генерации (тёплые/холодные), иначе крупные области уходят в чужой цвет.
- Опции `sprite_pipeline.py` для боя: `--cell-w 96` (ячейка 96×64 под меч и дугу взмаха; ступни и центр те же), `--ref-frame N` (рост задаёт кадр N, где оружие не торчит за силуэт — для атак), `--anchor body` (выравнивание по корпусу — для атак и всего, где меч поднят над головой), `--grid` (лист-сетка: строки сохраняются), `--flip 10,11` (отразить кадры), `--smooth 9` (сгладить слишком детальную генерацию; фон заливается контуром). Палитру можно снять с генерации — медианным квантованием (так сделана `drowned`).
- Ещё опции: `--cell-h 80` (меч над головой; ступни на 4 px выше низа ячейки), `--rows N` (резать сетку на N равных полос, если капли/брызги склеивают строки), `--holes-tolerance 3` (убрать чисто белый фон внутри дуги взмаха, не трогая белую шерсть Рэя). Лист Рэя для боя — ячейка 96×80.
- GIF строки листа: `python Tools/sheet_gif.py <лист> --cell-w 96 --cell-h 80 --row 0`.
- Шрифты: интерфейс — Public Pixel; журнал — First Time Writing (`assets/fonts/first_time_writing/`, импорт со сглаживанием, в коде FontVariation с embolden 0.7).
- Рост в `--height`: Рэй 48, Вельмор 56, Лиара 46. Для тёмных персонажей (Вельмор) добавлять `--holes` — убирает просветы фона между прядями; для белой шерсти Рэя не включать.
- Превью: `python Tools/preview_characters.py ray velmor liara` (виды + ходьба, GIF).
- Иконки предметов и скиллов: `python Tools/icon_pipeline.py "Арт/Генерации/<лист>" --names icon_a,icon_b,...` → 14×14 в `assets/ui/` поверх заглушек (палитра `icons`). Промпты — `Литература/ICON_PROMPTS.md`. Заглушки рисует `Tools/ui_atlas.py`; уже существующие иконки предметов/скиллов он не трогает (перерисовать заглушки — `--force`).
- Кадры анимации: `sprite_pipeline.py ... --height <рост вида из базового листа> --anchor head` (выравнивание по голове, чтобы кадры не дёргались), затем `python Tools/set_anim_row.py <кадры> <лист анимаций> --anim walk --dir side` вставляет их в строку листа.

## Инвентарь и журнал
- Данные — ресурсы в `res://data/`: `items/` (`ItemData`), `skills/` (`SkillData`), `souls/` (`SoulData`), `journal/` (`JournalEntry`), `maps/` (`JournalMap`). Поиск по id — `ContentDB`. Стартовые наборы создают `Tools/godot/build_demo_content.gd` и `Tools/godot/build_journal_content.gd` (ПЕРЕЗАПИСЫВАЮТ файлы с теми же id — после ручных правок автора не запускать).
- `PlayerState`: инвентарь, экипировка (слоты weapon, cloak, armor, amulet, relic_1, relic_2 → характеристики), души, хотбар (ссылки на SkillData/ItemData), отметки смертей с позицией (`die(at)`). Стартовый набор — константы START_* в `player_state.gd`.
- `JournalState` (автозагрузка): открытые/прочитанные записи, исследованные/намеченные комнаты; `MapTracker` в сцене отмечает комнаты по позиции игрока. Сохраняется в `SaveGame` (ключ `journal`).
- Карты журнала Рубежа (этаж 1), Брода и таверны — `python Tools/journal_maps.py` из `rubezh_layout.py` / `village_layout.py` (→ `data/maps/<id>.tres`; заметки Рэя — `NOTES` там же). Проходы (`passage: true`) рисуются без номера и не идут в список. Генераторы уровней ставят карту в `Book` и `MapTracker`. После правки планировки — перезапустить скрипт и пересобрать сцену.
- Книга Рэя — одна на персонажа и журнал: узел `Book` (`scripts/ui/book/book.gd`, CanvasLayer в сцене локации). Рамка, 8 закладок (4 слева — Рэй, 4 справа — журнал: записи, люди, улики, бестиарий), крестик, подсказки клавишами; страницы строят `book/character_pages.gd` и `book/journal_pages.gd`. Tab/I/View — разделы Рэя (журнал — Q/E или «Журнал» в паузе), M — карта во весь экран (`Book.open_map()`: карта мира, если есть узел группы `world_map`, иначе карта места `LocationMap` — `journal_pages.build_map`), Q/E и LB/RB — все закладки по кругу, Esc/B/крестик/клик мимо — закрыть (сначала отменяет назначение в хотбар). Ввод книги — в `_input`, иначе Tab съедает навигация фокуса. Пауза открывает книгу через `open_half()` и не перехватывает Esc, пока книга открыта.
- Кнопки для мыши и касания: `RoundButton` (книга/карта/меню в HUD), `CloseButton` (крестик во всех окнах), ячейки хотбара кликабельны (`HotbarSlot.pressed`; в хабе отключены). Подсказки клавиш — `KeyGlyph` по автозагрузке `InputGlyphs` (сама переключает клавиатуру/геймпад).
- Окна растягивать на весь экран через `set_anchors_and_offsets_preset(PRESET_FULL_RECT)`: просто `set_anchors_preset` оставляет нулевой размер, если родитель уже в дереве (так съезжали настройки в паузе).

- Кладка: `corbels`, `band`, `pier` (ступенчатый контрфорс, низ — по настоящей поверхности скалы, `rock_surface`, но не длиннее 40 px), `tracery`, `oculus`, `coping`, `strut`, `tower_house`, `AUTO_TURRETS`, скошенные основания башен (`foot`). Круглое: `prism(round_axis=...)` — сглаживание и развёртка вокруг оси (без швов проекции и растяжения), тон на всю деталь, а не на грань (иначе полосы). Основания: `ground_under`, `rock_top`, `stand_z`, `upper_solids` — залы, башни-дома, стены и башни уходят до скалы, внешние опоры ставятся только там, где есть на что встать. `HALL_ACTUAL`: мелочь на крышах считается от настоящего конька, он бывает срезан контуром. Обломки `jag_wall` и `broken_ring` — косой неровный излом, без ступенек; у башни на отроге `course` кладёт излом по рядам кладки. Башня на отроге (`build_spur`, таблица `SPUR`): юбка в скале, два пояса, окна над нижним, верх снят с арта по азимутам. Аркада рядом: `arcade(top_fn=...)` с рваным верхом `skyline`, обрамления, импосты и базы столбов. Случайные детали — генератор `R`, его нельзя затенять локальной переменной; у каждой части своё зерно, поэтому правка лестницы не перемешивает верхний ярус. Обломки `rubble` ложатся на готовую скалу (`rock_surface`, луч по `Rock`).
- Верхний ярус (просьба автора, 2026-11-07): не ряды домиков, а разные здания. `varied_hall` даёт каждому залу ряда сдвиг, свои размеры и уклон, часть разворачивает коньком вдоль фронта (`_HALLS_CACHE` — порядок и случайности постоянны). `hall_style`: `tracery` (большое окно с переплётом — только `FOCAL_HALLS` и редкие широкие залы), `lancet`, `tiered`, `blind`, `ruin` (на западе; `hall_ruin`, `ruin_wall` — сквозная арка). Фасады — `gable_face`, неф — `aisle`, угловые контрфорсы — в `hall`. `TOWER_HOUSES`: зубцы или шатёр, окна рядами, разбивают ряды щипцов. `turret(cap=...)`: шатёр с раструбом или зубцы. Сетка стен: `prism(rows=..., ao=...)`, `wall_strip`, `dense_rect`, `aorange` — цвет задан в вершинах, поэтому пятна сырости и мох ложатся только на стену с сеткой, а затенение считается по её видимой части. Внутренние стены идут против часовой, иначе ниши и контрфорсы смотрят внутрь.
- Растительность: плющ и лианы `build_ivy` (атлас `ExtrasFoliage`, на круглых стенах плитки по дуге, плитка без камня под углами не ставится). Растения пака — `Tools/blender/castle_veg.py` (запуск после `build`): точки берутся с граней скалы, смотрящих вверх, каждая проверяется лучом вниз; `on_walkway` убирает их с лестницы и площадок. Связанные копии в коллекции `CastleVeg`, библиотека `CastleVegLib`, расстановка `Арт/Blender/castle/castle_nature.json` в формате `world_nature.json` (в мир сама не попадает). Кусты, цветы, лиственные, сухая трава, широкие листья и мёртвые деревья пака не взяты: в этом масштабе кислотные, бежевые и рыжие точки. Листва пака тёплая и яркая, `DARKEN` затемняет и холодит её только в сцене замка; при встраивании этим растениям нужен свой материал, сейчас `NatureScatter` красит только по яркости. Материалы `Veg_*` руками не удалять: слоты библиотеки опустеют, и всё станет материалом `Rocks` (бурые карточки); `veg_material` сам обновляет оттенок, для полной пересборки сначала очистить `CastleVegLib`. Порядок пересборки: `build` → `castle_veg` → `castle_audit` → `sil`, `views` → `castle_site` `render`. После перезапуска Blender `build` пишет `castle.blend` заново из пустой сцены: `CastleSite` надо собрать снова (`castle_site`, `MODE` build).
- Мелочь (пинаклы, коньки залов) ограничена верхними контурами исходников: `Tools/blender/castle_profiles.json`, функция `limit_tip`. Вершины шпилей сопоставлены между видами по высоте.
- Проверка висящих деталей: `Tools/blender/castle_audit.py` (`MODE` check → `Арт/Blender/castle/audit.json`; `shots` → крупные планы). Считает группы, не касающиеся скалы; низы объёмных деталей в воздухе (по настоящей геометрии); плющ без камня; растения без опоры. Гонять перед каждым показом автору: на глаз висящее легко пропустить. Ожидаемый остаток, снаружи не виден: оторванных групп 0, 5 низов: край площадки у моста (в мире стоит на земле, в этой проверке земли нет), пол внутри башни на отроге, 3 камня в обломанном верхе (лежат в полой стене).
- Сверка: `python Tools/castle_compare.py` → `overlay_*.png`, `iou.json` (`profiles` — переснять контуры). Предел по самим исходникам: спереди/сзади совпадают на 0,915.
- Палитра (решение автора 2026-11-06): как в главном меню, холодная; PROJECT_BIBLE для Рубежа: «холодный синий → стальной серый». Замеры меню, камень: тон 202–218°, насыщенность 0,14–0,17, массы (27, 31, 37) и (40, 44, 49), светлые грани (85, 104, 106). Исходные текстуры Рубежа уже такие (кирпич 66, 75, 84); ранний тёплый подогрев под арт был ошибкой. Текстуры: `python Tools/castle_textures.py` → `Арт/Blender/castle/tex/`: холодные варианты текстур Рубежа и сланец, 128 px = 3,2 м, Closest; у скалы контраст снижен (рисунок крупно даёт геометрия). Развёртка `box_uv` — по оси нормали грани, в метрах; круглые детали — вокруг оси. Цвет в углах граней (атрибут `Col`): множитель текстуры, запечённое затенение. Окна и ниши — плоские грани поверх стены. Порядок вершин важен: в Godot задние грани отсекаются, проверка — режим `cull`.
- Примерка: `Tools/blender/castle_site.py` (`MODE` build, render) в том же файле, коллекция `CastleSite`: рельеф из `world_heights.npy`, гладь, мост и старая крепость — копии объектов из `world.blend` (только чтение). ## Структура проекта
- `scenes/levels/`, `scenes/player/` — сцены; `scripts/<область>/` — скрипты; `assets/sprites/` — спрайты.
- Ввод (`project.godot`): движение — WASD, стрелки, левый стик (крестовина отдана предметам); `dash` — пробел/ПКМ/B; `run` — Shift/L3; `attack` — ЛКМ/J/X; `interact` — E/A; `skill_1..4` — Q R F C / Y LB RB RT; `item_1..4` — 1–4 / крестовина ↑→↓←; `inventory` — Tab/I/View; `journal` — M; `pause` — Esc/Start; `ui_tab_prev/next` — Q/E, LB/RB; `ui_accept` — Enter/пробел/A и `ui_cancel` — Esc/B (переопределены: у движка нет кнопок геймпада для них)
- Интерфейс (UI_SPEC.md): автозагрузка `PlayerState` (`scripts/core/player_state.gd`) — HP, энергия души, отметки смерти, гелиосы с потерями по сложности, демо-скиллы и предметы; HUD (`scripts/ui/hud.gd`) только читает его сигналы. UI рисуется в UI-пикселях внутри `UIScaler` (целочисленный масштаб, холст 640×360 при ×3; `min_canvas` не даёт окну вылезти за экран — по умолчанию 400×264, у книги больше). Тема — `assets/ui/theme.tres` (собирает `Tools/godot/build_ui_theme.gd`), графика — `Tools/ui_atlas.py` → `assets/ui/`. Шрифт Public Pixel (8/16 px, импорт без сглаживания), подписи в ячейках — `TinyFont` 3×5.
- Отладка HUD — в мастер-меню (O): урон, смерть, +25 гелиосов, новый спуск, Перепутье.
- Анимации персонажей: `scripts/animation/directional_sprite.gd` (класс `DirectionalSprite`). В игре у Рэя лист боя 96×80 (`ray_combat.png`, см. «Бой»); исходные листы ходьбы: ячейки 64×64, столбцы — кадры (до 4), строки — анимация × направление (down, up, side) в порядке `idle, walk, run, dash`. Временные листы собирает `Tools/make_placeholder_anim.py`.

## Соглашения
- Спрайты персонажей: рост около 48 px, 4 направления (влево = отражённое вправо). Арт генерируется ИИ и дорабатывается вручную.
- Окружение: 3D-геометрия с пиксельными текстурами (фильтр nearest).
- Управление: клавиатура, мышь и геймпад одновременно — каждое действие в InputMap должно иметь привязки для клавиатуры и геймпада, и для мыши там, где это осмысленно (движение мышью не делаем).
- 2.5D: 3D-мир, персонажи — `Sprite3D` с `billboard = Y`, `shaded = true`, `alpha_cut = discard`, фильтр nearest (пиксель-арт).
- Камера «диорамы»: фиксированный наклон, FOV ~30, DOF ближнего и дальнего плана.
- Атмосферу локаций задавать через `WorldEnvironment` (туман, glow) по палитрам из PROJECT_BIBLE.
- Комментарии и имена узлов в сценах можно писать по-русски, идентификаторы в коде — на английском.
- Все персонажи — антропоморфные звери.
